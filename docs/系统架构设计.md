# 系统架构设计

> 足球数据分析与 AI 预测系统 ｜ 整理日期：2026-09-10

## 一、总体架构

系统分为**数据层 → 存储层 → 分析/预测层 → 服务层 → 展示层**五层，另有**定时任务**贯穿全局：

└───────────────┬──────────────────────────────────────────────────┘

                │
                ▼
┌──────────────────────────────────────────────────────────────────┐
│              分析与预测层 (analysis / prediction)                  │

## 二、数据库设计（核心表）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `leagues` | league_id, name, name_en, country, season | 10 个赛事 |
| `teams` | team_id, league_id, name, name_en, logo_url, stadium, capacity, founded, elo_rating | 259 支球队 |
| `players` | player_id, team_id, name, position, number, age, photo_url, stats_json | 2,991 名球员 |
| `matches` | match_id, league_id, season, matchday, date, home/away_team_id, home/away_goals, **status**, **home/away_xg**, **home/away_xg_proxy**, ht_home/ht_away, home/away_shots, home/away_sot, home/away_corners, home/away_yellow, home/away_red, stats_json | 12,564 场 |
| `standings` | league_id, season, team_id, rank, played, won, draw, lost, goals_for/against, goal_diff, points, form | 384 行 |
| `transfers` | player_name, from/to_team_name, transfer_date, transfer_type, season | 343 条 |
| `predictions` | match_id, model_version, pred_home_win/draw/away_win, pred_result, actual_result, **hit**, **is_backtest**, features_json | 1,803 条 |
| `qxz_fixture_map` | match_id, qxz_fixture_id, kickoff | 本地 ↔ 球小策比赛映射 |
| `qxz_match_pack` / `qxz_lineups` | match_id, fixture_id, payload(JSON) | 付费增强数据 |

**状态约定**：`NS` 未开赛 ｜ `1H/2H/HT` 进行中 ｜ `FT` 已完场。

## 三、API 设计

| 路由 | 说明 |
|---|---|
| `GET /api/leagues/` | 联赛列表 |
| `GET /api/teams/search?name=` / `GET /api/teams/league/{id}` | 球队检索/按联赛 |
| `GET /api/players/search?name=` | 球员检索 |
| `GET /api/matches/upcoming?days=7` | 未来赛程（兼容 `NS` 状态） |
| `GET /api/matches/live` | 实时比分 |
| `POST /api/predictions/predict` | 单场预测（含 SHAP 解释） |
| `GET /api/predictions/model/info` | 模型信息 |
| `POST /api/agent/chat` | AI 智能问答（LangChain Agent） |
| `WS /ws/live-scores` | 实时比分推送 |

## 四、前端页面结构（管理端）

| Tab | 功能 |
|---|---|
| 🏠 今日预测 | 未来 3 天比赛 + v2 预测概率 + 置信度 |
| 📅 比赛数据 | 多条件筛选（联赛/赛季/赛果/球队/日期）+ 统计卡 + 比分/半场/射门/射正/角球/xG + CSV 导出 |
| 👥 球员与球队 | 队徽 + 球场/容量/成立年 + 完整阵容（含头像）+ **本赛季排名联动** |
| 🔮 预测复盘 | 命中率总览、分联赛/分类型命中率、最近结算明细、一键回填 |
| 🏆 积分榜 | 4 个赛季 × 5 联赛切换 |
| 🧠 赛前分析 | 球小策赛前全景包（预测首发/伤停/战术，兼容"未就绪"状态） |

## 五、技术栈

| 层级 | 技术 |
|---|---|
| 后端框架 | FastAPI + Uvicorn |
| 数据处理 | Pandas + NumPy |
| 数据库 | SQLite（SQLAlchemy ORM，可通过 `DATABASE_URL` 切换 PostgreSQL/MySQL） |
| 机器学习 | XGBoost（三分类）+ scikit-learn（泊松回归做代理 xG） |
| 可解释性 | SHAP（TreeExplainer） |
| 前端 | Streamlit（用户端 + 管理端） |
| 定时任务 | APScheduler（BackgroundScheduler，随 FastAPI 生命周期启动） |
| 实时通信 | WebSocket |
| 数据源 | football-data.co.uk / Football-Data.org / TheSportsDB / 球小策 |

## 六、关键设计取舍

1. **CSV + SQLite 双轨**：训练与特征工程走 `all_matches.csv`（便于复现与版本管理），应用查询与展示走 SQLite（便于检索、聚合与外部工具如 Navicat 查看）；
2. **无泄漏优先**：所有特征严格使用"该场比赛之前"的信息，Elo 逐场递推、统计量 `shift(1)`，避免用未来数据预测过去；
3. **训练/推理一致**：预测时把待预测比赛作为"占位行"追加到历史数据尾部，用与训练完全相同的代码路径计算特征，杜绝特征错位；
4. **配额友好**：多源分层 + 请求门控 + 本地缓存 + 预算上限，使系统在免费额度内可持续运行；
5. **演示兜底**：无 API Key 时可切换到演示模式生成确定性赛程，保证系统离线也能完整演示。
