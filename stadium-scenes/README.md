# 球场四景 · 场景动画（基于同一张球场实拍）

四个**各自独立**的场景动画：**白天 / 黄昏 / 黑夜 / 雨天**。
每个场景一个自包含 HTML（照片与全部代码内联，**双击即可运行，不需要服务器**）。

```
stadium-scenes/
├─ index.html          ← 四景入口（四张卡片，点进去就是对应场景）
├─ day.html            ← 场景 1：白天·阳光充沛
├─ dusk.html           ← 场景 2：黄昏·落日余晖
├─ night.html          ← 场景 3：黑夜·灯火通明
├─ rain.html           ← 场景 4：雨天·乌云细雨
├─ assets/stadium.jpg  ← 原始球场实拍（1536×1024，298 KB）
├─ src/                ← 源码（build.mjs 把它们内联成上面四个页面）
│   ├─ util.js         噪声/云精灵/光晕/模糊/亮部提取等工具（window.SU）
│   ├─ scenes.js       四套场景参数表（window.SCENE_PROFILES）
│   ├─ engine.js       渲染引擎与照片锚点（window.SEngine / window.SANCHORS）
│   ├─ weather.js      黑夜灯光 + 雨天雨滴（window.SNight / window.SRain）
│   ├─ shell.css       界面（标题卡 / 场景切换 / 控制条 / 诊断）
│   └─ boot.js         启动、URL 参数、快捷键、诊断上报
├─ build.mjs           node build.mjs  → 生成 4 个场景页 + index.html
├─ tools/              截图与性能工具（见下）
└─ shots/              验收截图与诊断数据
```

## 运行

- **直接双击** `index.html`（或任意 `day.html` / `dusk.html` / `night.html` / `rain.html`）。
- 四个场景页**没有任何面板**：进去就是整屏画面（标题卡、切换页签、底部控制条、右下状态栏全部移除，只剩画面本身；只有真出错时顶部才会弹出报错条）。
- 快捷键仍在：`空格` 暂停 / 继续 · `1`~`4` 切换场景。
- URL 参数：`?t=12` 定格第 12 秒 · `?speed=0.5` 云速 · `?rain=0.6` 雨量 · `?glass=0` 关闭玻璃雨滴 · `?fx=0` 关闭暗角与颗粒 · `?rays=0` 关闭体积光（白天）· `?nohud=1` 隐藏报错条。

修改源码后重新生成页面：

```bash
cd stadium-scenes
node build.mjs
```

## 四个场景各自做了什么

### 1. 白天（day）— 阳光充沛、球场灯全关
- 素材是一张**光线明显的白天实拍**（`assets/stadium-rays.jpg`，1920×1280），直接作为底板使用：不套分级、不叠色、不加暗角与颗粒 —— 画面与原片**逐像素基本一致**（MAE 2.3/255，整幅均值 [142.3,157.9,145.5] vs 原片 [142.4,158.0,145.4]）。
- **云静止不动**：照片里的云就是原样（不再抠云、不再平铺飘动），两条云层 alpha 归零后引擎连云精灵都不构建。
- **球场灯全部关闭**：原片里灯本来就是关的，不需要额外压暗。
- **体积光（WebGL）**：移植用户提供的 `LightRays` 组件（同一个 fragment shader：`rayStrength` 双采样 + 鼠标方向混合 + 亮度渐变），独立一层的 `src/rays.js`，用原生 WebGL 画全屏三角形，靠 CSS `mix-blend-mode: screen` 叠在画面上方（`#rays`，z-index 5）。
  - **参数照组件示例原样**：`raysColor #ffffff`、`raysSpeed 1`、`lightSpread 0.5`、`rayLength 3`、`followMouse`、`mouseInfluence 0.1`、`noiseAmount 0`、`distortion 0`、`pulsating false`、`fadeDistance 1`、`saturation 1`；只把 `raysOrigin` 按原片的光位改成 **`top-left`**（anchor `[0,-0.2h]`、dir `[0,1]`，光自左上斜向右下）。
  - 组件那份是叠在**深色底**上，这里底是**明亮的照片**，所以：① 用 `screen` 把光加在天空上（白色不会糊住天空）；② `intensity`（移植时加的总强度旋钮）取 **2.2**，让扇形光在亮底上照样看得见。
  - 只加光、不遮画面：光只落在左上天空带（`clip 0.34`），整幅均值只抬高约 2/255，草皮不受影响。
  - **WebGL 不可用时自动退回 canvas2d**：`_drawRays` 用**同一套扇形几何**（左上原点、11 条细光柱、`spread 0.135`/`len 0.85`/`alpha 0.30`、随鼠标平移旋转），所以没有 WebGL 的机器看到的是一样的扇形光；`?rays=0` 可切到这个 2D 版对照。
- **草坪光影带（`sunPatch`）本版停用**：画面 = **原片 + 左上角体积光**，草皮保持原片自己的光照，不做任何加减光。
  - 逐像素对照（按引擎的 cover 贴合规则取裁剪框，`iy = -40`）：整幅 **MAE 3.6/255**、草皮 **3.27/255**、右侧天空 **0.39/255**；整幅均值 渲染 [144.0,159.6,147.4] vs 原片 [142.4,158.0,145.4]（+1.6 就是左上那束光）。
  - 这套"互补平行渐变带"（`screen` 加亮受光侧 + `multiply` 压暗背光侧，共用同一条分界线、随鼠标平移）代码仍保留在 `_drawSunPatch` 里，day profile 中注释着完整参数（`x/y/angle/mid/soft/alpha 0.20/shadow 0.40/mx 0.15/my 0.05`），需要时把 `sunPatch: {…}` 打开即可。
- **只有"光"随鼠标轻微晃动**：镜头完全不动（`camS 1.0 / camX 0 / camY 0`），鼠标只驱动太阳辉光与体积光的位移/朝向；曝光不随鼠标变（`mouse.exposure = 0`）。
- 地面云影同样关闭（照片里本来就带着云影）。
- 抠云流程（`tools/prep_day_photo.py` + `assets/plate.jpg` / `assets/clouds.png`）保留在工程里备用：云区之外与原片 **MAE 3.2/255**、浓云区 **MAE 12.1/255**，需要"云会飘"的版本时可以切回去。

### 2. 黄昏（dusk）— 与白天同一套光照逻辑，落日色调
- 光照联动逻辑与白天**完全相同**（同一个 `sunVis` 通路），只是换成落日色：天空保持原片的暖橙渐变，云被夕阳染成金紫两色（`lit1 [255,214,170]` / `shade1 [130,112,136]`）。
- 光柱/光带随云层明暗忽明忽暗，呈"余晖被云断续遮住"的观感。
- 球场灯同样关闭。

### 3. 黑夜（night）— 球场灯全开、城市灯火通明
- **以球场灯为唯一主光源**：从原片提取灯带亮部做灯罩发光（`lightMask`），再加逐灯球状辉光、灯带泛光、向草坪斜射的**光锥**、草地上的**光池**；这些亮度同样被云遮挡调制（云过灯暗）。
- **城市高楼全部亮灯**：从原片提亮部得到窗光底图，再自建"楼体暗像素遮罩内撒窗点"合成整城亮灯；另有约 160 个窗点在做实时亮灭闪烁，城市泛光被裁切在城市带内绘制。
- 天空有星空（只布在天际线以上），天际线附近有一层暖色城市光雾。

### 4. 雨天（rain）— 乌云、真实的雨、溅落、玻璃雨滴
- 乌云压顶：云层加密压低，整体压成冷灰蓝调，天光压暗。
- **雨**：2600 颗雨滴粒子分远/中/近三层，每层按 3 档透明度用 `Path2D` 批量描边（不是逐个 stroke），近处的更粗更快更斜；另有极淡的解析式双闪闪电。
- **落在草坪上的溅落**：雨滴落地后按 `pitchPoint()` 落到真实草皮位置，画出扩散的水环 + 中心溅起的水花 + 3 颗抛物线抛起的水珠。
- **贴在"玻璃"上的雨滴**：30 颗大小不一（半径 4.5~30 px）的雨滴，
  - 用**离屏小画布**逐个渲染：凸透镜折射（把身后画面放大 1.7 倍、倒转、以 0.70 透明度叠回来，所以是"透亮"的而不是不透明球）、中心聚光、底部焦散亮弧、上缘细暗边、一大一小两点高光；
  - 边缘用 `destination-in` 径向羽化，避免"肥皂泡"式的硬圆边；
  - 生命周期为 停留 → 滑落（珠体拉长，拖出一道湿痕 + 沿途残留的竖向小水珠）→ 变淡消失；
  - 近景雨丝也画在这一层（跟随镜头，玻璃雨滴不跟随，符合"贴在玻璃上"的视觉）。
- 另有雾带、湿草反光与流动水光。

## 技术要点

- **纯 Canvas 2D**，无外部依赖、无构建产物依赖，照片以 base64 内联。
- **云**：`U.cloudGrid()` 生成 value-noise 分形噪声场，`U.cloudSprite()` 转成带受光面/背光面的云精灵（含 `warp` 扭曲、`fade` 纵向淡出，保证云只出现在天际线以上、不会压住楼群与看台）。
- **光照联动**：`_sampleOcclusion()` 在云遮罩网格上采样"太阳被挡了多少" → 指数平滑 → `state.sunVis` 驱动光源辉光/光柱/云亮度/曝光；用 `U.hash2` 与相位保证云影随云一起移动。
- **性能**：`resize()` 里按 2.6M 像素预算限制 devicePixelRatio；全屏合成层（城市灯、灯带泛光、颗粒）都做了裁剪或用 `createPattern` 一次填充；云精灵只绘制有内容的上段。

## 验收（`shots/`）

- `day.png / dusk.png / night.png / rain.png`：四景 t=9s 的定格帧（1280×720，`errors: 0`）。
- `*_t39.png`：t=39s 的帧，用于对比云的位置变化。
- `diag.json`：每帧的运行时诊断，含云遮挡联动证据：

  | 场景 | t=9s sunVis / occ | t=39s sunVis / occ | 云层相位(层1/层2/影) 9s → 39s |
  |---|---|---|---|
  | day | 0.465 / 0.535 | 0.812 / 0.188 | 66/152/33 → 288/659/144 |
  | dusk | 0.465 / 0.535 | 0.812 / 0.188 | 66/152/33 → 288/659/144 |
  | night | 0.507 / 0.493 | 0.391 / 0.609 | 66/152/33 → 288/659/144 |
  | rain | 0.636 / 0.364 | 0.800 / 0.200 | 124/249/62 → 539/54/270 |

  `off1/off2/offS` 是两层云与云影各自的**平铺相位**（0~1024 循环、两层速度不同，所以会错开、也会回绕）：
  同一场景两个时间点相位不同 = 云确实在飘；`sunVis` 随相位变化 = 光照确实被云实时调制
  （例如 day/dusk 从 0.465 升到 0.812：云让开、太阳露出来、草坪随之变亮）。
- `thumbs/`：index.html 用的 640 宽缩略图。
- `live.json` + `node tools/live.mjs`：**rAF 动画循环实测**（不注入定格脚本，正常加载页面后静置观察）。
  实测结果（无头 Chrome，软件渲染）：

  | 场景 | 实测 fps | 每帧 | 两次采样的云相位 | 云遮日 sunVis |
  |---|---|---|---|---|
  | day | 39.5 | 22.8 ms | 22.2/51.0 → 37.2/85.3 | 0.328 → 0.362 |
  | dusk | 35.0 | 24.6 ms | 22.6/51.8 → 37.5/85.9 | 0.328 → 0.363 |
  | night | 26.5 | 39.9 ms | 22.4/51.3 → 37.4/85.6 | 0.550 → 0.536 |
  | rain | 26.5 | 31.1 ms | 41.7/83.4 → 70.0/140.1 | 0.362 → 0.445 |

  四景的云相位都在持续变化 = 动画真的在跑；`sunVis` 同步变化 = 光照真的跟着云走。

### 工具

```bash
node tools/shot.mjs                       # 四景各拍 t=9、t=39（Chrome DevTools 协议，需本机 Chrome）
node tools/shot.mjs rain:9,24,60          # 指定场景与时间点
node tools/perf.mjs                       # 逐段性能剖析
node tools/shotpage.mjs index.html shots/_index.png 1440 1050   # 任意本地页面截图
python tools/thumbs.py                    # 重新生成 640 宽缩略图
python tools/prep_day_photo.py            # 从白天实拍抠出云层（plate.jpg + clouds.png + skyline.json）
python tools/check_day_assets.py          # 抠图质量对比（输出 1:1 对照条 shots/_dayband_*.png）
node tools/live.mjs                       # 静置实测：rAF 是否真在跑、云相位/sunVis 是否在变
node tools/mouse.mjs day                  # 验证鼠标联动：rAF、事件通路、画面亮度响应幅度
node tools/inspect.mjs day "<表达式>"      # 在场景页里求值，确认运行时真实状态
```

> 无头 Chrome 需在沙箱外运行（受限沙箱下 Chrome 无法创建命名管道）。性能数字取
> SwiftShader **软件渲染**（1280×720、dpr=1、30 帧平均）：day ≈ 24 ms、dusk ≈ 36 ms、
> night ≈ 46 ms、rain ≈ 40 ms —— 这是**保守上界**，真机浏览器为 GPU 合成会明显更快。
