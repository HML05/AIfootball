## 1. 静态审计

### 1.1 控件语言耦合审计（判据 A）

**脚本**：`audit_widget_keys.py` v3。v3 相对早期版本的关键升级是**作用域内变量解析**——`st.*` 的 options 是否「随语言变化」，需要看该 options 实参引用的变量在**同一作用域内**是如何被赋值的。若不做作用域隔离，同名变量（例如 `admin.py` 中两处都叫 `names` 的局部变量）会互相污染，产生误报。

**审计范围**：`app.py`、`admin.py`、`theme.py`、`i18n.py`；跳过 `*.bak` / `*.pre` 备份文件。

**结果**：

```
AUDIT_EXIT=0
检查 2 的正确写法(有 format_func, 显示名随语言但值语言无关) —— 通过:
  app.py:471  st.selectbox   选择联赛    (pick_i,  行号值 + format_func)
  app.py:561  st.selectbox   球队 A      (ai,      行号值 + format_func)
  app.py:564  st.selectbox   球队 B      (bi,      行号值 + format_func)
  app.py:761  st.selectbox   选择球队    (sel_i,   行号值 + format_func)
OK: 未发现 (1) keyless 且随语言变化、或 (2) options 值随语言变化而无 format_func 的控件
```

**判定**：**通过**。4 处命中的是「有 `format_func`、显示名随语言但值语言无关」的**正确写法**，脚本将其单列为 intentional 而非 problem。

### 1.2 i18n 覆盖率审计（判据 B）

**方法**：AST 解析全部 `t()` / `tr()` / `i18n_s()` / `txt_i()` 调用，逐一检查其首参（中文原文）在 `EN` 字典中是否有对应词条，或调用处是否直接给了 `en=` 第二参；同时扫描 `st.*` 控件实参中的**未包裹中文**字面量。

**结果**：

```
EN 词条总数                        : 716
[A] t() 漏译(缺 EN 且无 en=)       : 0 处
[B] st.* 真·裸中文(未包裹)         : 1 处
      i18n.py:709 st.selectbox   ['Language / 语言', '中文']     ← 语言选择器自身, 有意
    st.* [FF] 有 format_func 且含中文 : 6 处
      app.py:266   st.radio        ['AI智能分析', '实时比分', '比赛详情']
      admin.py:256 st.radio        ['API接口测试', '数据库管理', '数据更新控制']
      admin.py:533 st.selectbox    ['全部']
      admin.py:536 st.selectbox    ['全部']
      admin.py:539 st.selectbox    ['主胜', '全部', '客胜']
      admin.py:1400 st.selectbox   ['无']
结论: t() 漏译 0 处; 真·裸中文 1 处
```

**判定**：**通过**。

- `[A] = 0`：所有词条调用都能在 EN 字典命中或自带 `en=`。
- `[B] = 1`：唯一命中为语言选择器本身（`Language / 语言` 必须同时展示两种语言标识，且「中文」是该选项的字面值），属**有意**，不构成缺陷。
- `[FF] = 6`：这些控件的 options 含中文**内部值**，但都配有 `format_func` 做显示名翻译——正是缺陷类 2 要求的正确形态（值语言无关、显示名随语言）。此前的静态审计曾把 `admin.py:1007` 判为 problem，根因是**同文件另一处同名变量 `names`（混淆矩阵轴标签）造成的解析污染**；v3 作用域化后误报消除，该处选择器也已重构为 `labels` + `sel_i` 的标准写法，双重确认。

### 1.3 样式单一源审计（判据 C）

| 核查项 | 方法 | 结果 |
|---|---|---|
| 是否存在第二份全局样式 | 在 `app.py` / `admin.py` 中检索 `<style>` 注入与 `st.markdown(..., unsafe_allow_html=True)` 的样式块 | **无**。全站样式唯一来源为 `theme.py` 的 `UNIFIED_CSS`，由 `apply_theme()` 注入一次 |

## 2. 运行时审计

### 2.1 双语 8 页逐页访存（判据 D）

**脚本**：`apptest_bilingual.py`。该脚本以 `AppTest.from_file` 驱动真实页面脚本，在**无界面环境下**逐页渲染并断言。

**工程要点（harness 局限的规避）**：AppTest 的 `Radio.index` 用**格式化后的 options** 去反查当前值；而本项目的 `format_func = lambda x: t(x)` 依赖 `st.session_state`，在脚本运行上下文之外调用会失败并回退为原始中文值，与英文 options 不匹配，从而抛出 `ValueError`。因此**只要“上一次运行的树”是英文态，再次运行就会踩坑**。脚本据此确立唯一约束：**所有渲染动作都发生在“前一次运行树为中文”的时刻**——语言、页面与额外控件状态在**同一次**运行内一并提交；需要探索取值时，每个候选都用**全新会话 + 单次提交**逐个探测。

**结果**：

```

  [zh] 比赛详情 OK      [zh] 比赛预测 OK      [zh] AI智能分析 OK    [zh] 实时比分 OK
```

**判定**：**通过**（24 / 24）。

三条关键结论：

1. **8 页 × 2 语言共 16 次渲染均无异常** —— 覆盖导航、筛选、图表、表格、空态、语言切换全链路。
2. **阵容指标卡在中英两态数值完全一致**（`27 / 8 / 7 / 8`）—— 证明「位置计数」走的是语言无关的位置代码（`pos_group`），而非显示名匹配；同时英文标签 `Players / Forwards / Midfielders / Defenders` 与词条表一致（注意是**复数**形）。
3. **导航持久化成立** —— `nav_page` 在切语言后保持 `球员分析`，且导航项显示为全英文。若 `key` 缺失（缺陷类 1），此处会回落 `首页概览`。

> **关于 `missing ScriptRunContext!`**：这是 Streamlit AppTest 无界面运行的常规告警，不影响断言，非缺陷。

## 3. 三类缺陷与修法

| 缺陷类 | 识别方式 | 修法 | 覆盖处数 | 状态 |
|---|---|---|---|---|
| **类 1**：keyless 控件的元素 id 随语言漂移 | 静态审计检查 1（无 `key` 且 label/options 含 `t()`） | 显式声明 `key=`，使元素 id 与语言解耦 | 侧栏导航 1 处 + 全站控件 | 归零 |
| **类 2**：options 的**值**随语言变化 | 静态审计检查 2（options 随语言变化且无 `format_func`） | options 改用**语言无关值**（行号 / 中文内部键），显示名交 `format_func` | 用户端 4 处 + 管理端 1 处 | 归零 |
| **类 3**：库内中文未经 i18n 漏斗 | 运行时双语回归（EN 态查中文残留） | 新增 `txt_i(v) = t(str(v))`，对所有取自数据库的中文枚举值过漏斗 | 联赛名 7 处 | 归零 |

## 5. 审计结论

**审计结论：通过。**

- **静态**：控件语言耦合缺陷（类 1 / 类 2）**0 处**；`t()` 漏译 **0 处**；样式单一源成立，无游离色值；四个前端文件 `py_compile` 通过。
- **运行时**：8 页 × 2 语言 16 次渲染无异常；阵容指标卡中英数值一致；导航持久化成立。合计 **24 / 24 PASS**。
- **三类静默缺陷**（控件 id 漂移、选项值漂移、库内中文未过漏斗）**全部归零**，且均已在审计脚本中固化为**可重跑的检查项**，后续 UI 改动可直接复验。

审计口径中唯一「未通过」项为 **0 项**；登记在案的 1 处裸中文与 4 处 intentional 命中均为**设计意图**，已在本报告 1.1 / 1.2 节逐条说明，不再重复计入缺陷。
