# FootballAI 界面信息架构评审（用户端 / 管理端）

评审对象：`http://127.0.0.1:8000/` 的界面（React 前端 + `/api/ui/*`）。评审时为 11 条路由；§6 的四项结构调整完成后用户端 7 个导航入口 + 4 个详情页 + 管理端 4 页签。
盘点方式：`python scripts/audit_webui.py`（逐页导出卡片顺序 / KPI 标签 / 表头行数 / 内部滚动块），截图见 `docs/webui/`。
结论先行：**排版（视觉）基本可用，问题集中在「信息架构」——管理端内容放在用户端、同一批指标出现在两页、KPI 口径与分页耦合、术语混用。**

## 3. 用户端应该展示什么（本次评审的核心）

**一条原则**：用户端回答四件事 —— ① 有什么比赛、结果如何（事实）；② 我们看好谁、有多看好（增值）；③ 球队/球员/联赛档案（可检索）；④ 我关注的队和人（个性化）。
**用户端不展示**：入库日志与同步状态、库表清单与记录占比、外部数据源清单、特征权重与混淆矩阵、覆盖率数字（除非作为「预测依据」解释）。

## 4. 目标结构（建议）

**用户端 7 个入口**：总览 · 赛程（含比赛详情）· 联赛 · 球队 · 球员 · 预测 · 实时
**管理端 4 个页签**（`/admin` 内）：数据总览 · 数据资产 · 模型注册表 · 系统与接口

四项结构调整（改动量从大到小）：

1. **`/reports` → 管理端「数据资产」页签**（用户端导航去掉「报告」）。
2. **`/agent` → 管理端「模型注册表」页签**；用户端把「模型如何工作」并入 `/predictions` 作为解释块。
3. **新增 `/matches` 与 `/matches/:id`**（赛程/赛果 + 单场详情），`/live` 收敛为「实时」短页或并入赛程页的 tab。
4. **新增 `/teams/:id`**（球队详情），与 `/players/:id` 对称。

第 1、2 项是「内容回家」（不新增能力，只挪位置）；第 3、4 项是补齐用户端闭环（库里 12,698 场比赛、231 支球队目前没有可点击的落点）。

### 6.1 比赛详情页二次排版（复核发现并修掉）

复核时用 Playwright 量整页高度：`/matches/9012` 整页 1,859px，而**左列仅约 510px、右列约 1,400px**，左列下方出现约 900px 空白 —— 原因是原结构把较矮的「记分板 + 历史交锋」放左列，把「模型预测 + 积分榜位置 + 双方近期比赛 + 快捷入口」全放右列；未开赛、无技术统计、无历史交锋的场次尤其失衡。

重排方案（`webui/src/pages/MatchDetail.tsx`）：① 记分板改为整页宽卡；② 下方两列 `lg:grid-cols-[minmax(0,1.35fr)_minmax(0,1fr)]`（断点由 1280 降到 1024，1280–1439px 笔记本也走双列）；③ 左列 = 模型预测 → 数据对比（无数据整块不渲染）→ 双方近期比赛，右列 = 赛季积分榜位置 → 历史交锋 → 快捷入口；④ 每张卡 `self-start`、两列容器 `min-w-0`（防长队名撑破列宽）。

实测（1600px 视口，`getBoundingClientRect().height`）：`/matches/9012` 左/右 934 / 934、`/matches/9107` 1,255 / 1,255、`/matches/16004` 881 / 881，列高差均为 0；整页高度 1,470 / 1,782 / 1,417px，三页 `errors` 空、坏图 0、横向溢出 0。遗留：`/matches/9012` 右列底部约 176px 空白（右列内容 758px < 左列 934px，属卡序决定的固有结果，在 200px 公差内）；空态「历史交锋」卡被 `EmptyState` 自带的 `py-10` 撑到 154px，若要压到 120px 需改 `webui/src/components/kit.tsx`（暂未动）。

### 6.2 登录闸门（在其外层新增的第 0 层）

用户要求「把登陆界面加上」后，在 7 个用户端入口之前加了一层登录：

- **未登录时唯一可达页面是设计稿那版登录页**（`docs/console/login.html`，球场底图 + 昼/暮/夜/雨四套天气 + 账号密码 / 扫码两个页签）；它由后端挂在 `/console`（只挂载不改文件），React 未登录时整页跳到 `'/console/login.html?next=<原地址>'`，登录后才进入「总览 / 赛程 / 联赛 / 球队 / 球员 / 预测 / 实时」。同源时两边共用 `localStorage['fauth']`；开发服（3000）跨源时该页回跳会附加 `?auth_token=`，由前端收下。
- **管理端入口（顶栏「设置」）只对 `role=admin` 显示**；`/admin*` 另有 `RequireAdmin` 守卫，非管理员看到「需要管理员权限」卡（含「换管理员账号登录」，带 `why=role`，登录页会说明原因）而不是白屏或空数据。
- 信息架构上不新增用户端入口，也不改变任何页面内部的面板归属 —— 只是把「谁能看到这些面板」这一层补上；公开面仅 `/api/ui/public/summary`（品牌 + 6 个总量）与队徽 `/api/ui/logo/*`。
- 验证：17 条路由体检通过（含 `/console/login.html` 未登录态）、26 个接口冒烟通过、登录流程 17 项断言（生产 8000）/ 16 项（开发 3000）全部通过（守卫跳转 / 错密码提示 / 登录回原地址并换成真实账号 / 已登录给「继续进入」/ 退出清态 / 非管理员权限卡）、登录页四套天气 + 扫码页签截图冒烟 0 错误。
