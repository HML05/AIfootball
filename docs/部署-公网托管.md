# 部署到公网（三条路线，按「想多快看到网址」排）

> 这份文档管的是**公网托管**：把系统放到一个别人点开就能访问的地址上。
> 已经有服务器、想用 systemd + nginx 的，看 `docs/deploy.md`（那份是「传统 VPS 上线手册」），
> 本文第 3 节是它的容器化版本，两者可以互相替代。

---

## 0. 先看结论：选哪条

| 路线 | 适合 | 成本 | 代价 | 本节 |
|---|---|---|---|---|
| **A. Render 免费容器** | 想今天就有个网址能发给别人看 | 0 元 | 512 MB 内存；闲置 15 分钟休眠，再访问要等 30~60 s 冷启动；磁盘非持久（用户头像会退回默认图）；数据库只读 | §2 |
| **B. 云服务器 + Docker Compose** | 要一个长期稳定、能写数据的地址 | 服务器费 | 要自己买机器、配域名与证书 | §3 |
| **C. GitHub Pages 静态展示** | 只想让人**看**界面长什么样 | 0 元 | **跑不了后端**：没有数据、没有预测、没有问答，只有静态页面 | §4 |

三条路线的第 1 步都一样：**先做数据包**（§1）—— 因为仓库里没有数据库和模型。

> **为什么一开始考虑的 Hugging Face Spaces 不可行（实测，不是听说）**
> 本机 `C:\Windows\System32\drivers\etc\hosts:71` 有 `127.0.0.1 huggingface.co`（Steam++ 加速工具写的），
> 于是 `huggingface.co` 直接解析到本机：HTTP 超时/502，`git ls-remote https://huggingface.co/spaces`
> 报 `fatal: unable to access ... error: 502`。同一条网络里 github.com / render.com / railway.app /
> koyeb.com / fly.io 都是 200 可达，所以路线改成「GitHub 存代码 + Render 跑服务」。

## 1. 前置：把数据打成一个包

**为什么必须打包**：`data/database/*.db`、`models/*.joblib`、`data/processed/*.csv` 都被 `.gitignore`
排除（`.gitignore:52-73`），仓库里没有它们 —— 没有数据库就没有比赛，没有模型就没有预测，
没有检索索引就没有问答。

```bash
# 在项目根目录（Windows PowerShell 同样可以）
python scripts/make_data_pack.py
```

本机实测输出：

```
[1/3] 准备打包内容（4 项）
      data/database/football.db → VACUUM INTO 副本 154.83 MB
      data/database/search.db   → VACUUM INTO 副本  16.16 MB
      原始合计 187.45 MB → %TEMP%\aifootball-data-pack-v1.tar.gz
[2/3] 完成：51.83 MB（压缩率 27.6%）
[3/3] SHA256 = bf1c7180507dbe2fb736ce0a654a4595ffdb75983fd87b7aacbcfa4e5c05f83c
```

包里正好 4 项：

| 内容 | 作用 | 缺了会怎样 |
|---|---|---|
| `data/database/football.db` | 业务主库，36 张表 / 181 万行 | 界面全是空的 |
| `data/database/search.db` | 中文检索索引（独立库，FTS5 + jieba） | 检索与问答不可用（容器入口脚本会自动重建一次，约几十秒） |
| `models/` | XGBoost 预测模型 + 评估报告 | 预测接口报「模型未加载」 |
| `data/processed/*.csv` | 预测特征输入 | 预测时缺特征 |

> 为什么用 `VACUUM INTO` 而不是直接拷 `.db`：运行中的 SQLite 带 WAL
> （`football.db-wal` 约 2 MB），直接拷主库会丢掉最近提交；`VACUUM INTO` 出来的副本自洽、无 WAL，还更小。

**上传成 Release 资产**（二选一，`make_data_pack.py` 跑完会直接把这两段打印出来）：


**校验**（列内容 + 确认 4 个关键文件都在；上传前后都能用）：

## 2. 路线 A：Render 免费容器（推荐，10 分钟左右）

1. 打开 <https://render.com> → 用 GitHub 账号登录（免信用卡）。
2. 右上 **New +** → **Blueprint**。
3. 选仓库 `HML05/AIfootball`（第一次会让你授权 Render 读仓库）→ **Apply**。
   Render 读到根目录的 `render.yaml`，按里面的定义建一个 Docker Web Service。
4. 建好后进服务页 → **Environment** → 给 `LLM_API_KEY` 填上你的 key（见下）→ Save。
5. 等服务变成 **Live**，点右上给出的地址（形如 `https://aifootball-xxxx.onrender.com`）。

`render.yaml` 里定好的东西（不用手点）：

| 项 | 值 | 为什么 |
|---|---|---|
| runtime / plan | docker / free | 免费档 = 0.1 CPU / 512 MB，够跑起来但算得慢 |
| region | singapore | 离国内近；该区域不可用时改成 oregon / frankfurt（**建好之后不能改**） |
| healthCheckPath | `/health` | Render 靠它判断服务是否活着 |
| autoDeployTrigger | `commit` | 推送到 main 就自动重新部署 |
| UI_REQUIRE_AUTH | `true` | 公开地址必须登录才能看数据 |
| AUTH_ALLOW_REGISTER | `false` | 关闭自助注册（要开新号就在库里加，或临时打开） |
| AUTH_RESET_SHOW_CODE | `false` | 不把重置码回显到页面 |
| ENABLE_DAILY_UPDATE / ENABLE_LIVE_SCORE_UPDATE | `false` | 免费实例别去刷外部数据 API |
| LLM_BASE_URL / LLM_MODEL | `https://api.deepseek.com` / `deepseek-flash` | 问答用 |
| **LLM_API_KEY** | `sync: false` | **不写进仓库**；Render 只在首次创建 Blueprint 时弹框让你填，之后要改去服务页 Environment。不填也能用（自动降级成检索摘要） |
| DATA_PACK_URL | Release 地址（§1） | 构建期下载数据包 |

**免费档的三条实情**（先知道，省得部署完才发现；数据来自 Render 官方
[blueprint-spec](https://render.com/docs/blueprint-spec) 与[免费实例页](https://render.com/docs/free)）：

- **0.1 CPU / 512 MB**：内存够（本机实测常驻 286 MB），但 **0.1 CPU 很小** ——
  计算类接口（预测、检索）在免费档上会明显比本机慢，界面首屏也可能要等几秒。
- **会休眠**：闲置 15 分钟实例停止，下次访问要等 30~60 s 冷启动，第一次打开慢是正常的。
- **磁盘不持久**：容器重建后 `data/uploads/`（用户上传的头像）丢失，头像会退回默认图；
  数据库只读使用，不受影响。要持久化就换付费档加 Disk，或走路线 B。
- **构建期会拉数据包**：约 52 MB，第一次构建要几分钟。

**部署后必做两件事**：

1. **改掉 admin 密码**：默认账号是 `admin` / `football2026`（超管，权限最大）。
   登录 → 点右上头像 → 账号设置 → 密码。默认密码是公开写在文档里的，不改等于门开着。
2. 可选：想用扫码登录，就在 Render 的环境变量里加 `AUTH_PUBLIC_BASE=https://<你的服务名>.onrender.com`
   （扫码链接要拼绝对地址；不加只影响扫码这一条路径）。

## 3. 路线 B：云服务器 + Docker Compose（要长期稳定用这条）

前提：一台 Linux 服务器（1 核 1 GB 起）、一个解析到它的域名、装了 Docker 与 Compose 插件。

```bash
git clone https://github.com/HML05/AIfootball.git && cd AIfootball
python scripts/make_data_pack.py                 # 打数据包
# 服务器上直接把包解开到项目里（也可以让容器构建期去 Release 下）
tar -xzf aifootball-data-pack-v1.tar.gz -C .
cp deploy/.env.example deploy/.env               # 填 DOMAIN / ACME_EMAIL / LLM_API_KEY
docker compose -f deploy/docker-compose.yml up -d --build
```

- `deploy/Caddyfile` 负责反代与**自动申请 HTTPS 证书**（`DOMAIN` 不填就退化成 80 明文，可先用 IP 验）。
- 容器入口 `deploy/entrypoint.sh` 启动前会打印一份**不含密钥**的有效配置，
  数据库/模型/索引缺失时给明确警告，索引缺了还会现场重建一次。

**两个坑（compose 文件里已经处理，改的时候别踩回去）**：

1. **别把空卷挂到 `/app/data`** —— 空目录会盖掉镜像里打好的 `football.db`，界面直接变空。
   现在只挂 `uploads`（头像）与 `logs`。
2. **要能写库就先落盘**：改密码、加账号都是写 SQLite。要么把宿主机 `./data` 整块挂上去，
   要么按 `docs/deploy.md` §11 的做法挂单文件并保留 `-wal/-shm`。

不想用容器、就想 systemd + nginx：直接照 `docs/deploy.md`（含备份、日常更新、排错）。

## 4. 路线 C：只要一个「能看的网页」→ GitHub Pages

Pages 只托管静态文件，**跑不了 FastAPI**，所以它不能替代 A/B。它适合做「作品展示页」：

- 把 `docs/webui/` 里的 22 张交付截图做成一个静态页面，说明各页面做什么；
- 或者把 `docs/console/`（登录页/总览/后台的设计稿，纯 HTML + 假数据）发布出去，
  点得动、能看交互，但没有任何真实数据。

做法：仓库 Settings → Pages → Source 选 `Deploy from a branch` → 选分支与目录（例如 `docs/` 下的静态目录）。
本文档不做进一步展开 —— 真要用的话把静态页面单独放一个目录，别让整个 `docs/` 都暴露出去。

## 5. 部署前先在本机按生产配置跑一遍（实测记录）

容器与云平台上的配置，本机可以一模一样地先验一遍，省得在云上猜：

```powershell
# PowerShell；把 7860 当成「容器里的那个端口」
$env:PORT="7860"; $env:UI_REQUIRE_AUTH="true"; $env:AUTH_ALLOW_REGISTER="false"
$env:AUTH_RESET_SHOW_CODE="false"; $env:DEBUG="false"
$env:ENABLE_DAILY_UPDATE="false"; $env:ENABLE_LIVE_SCORE_UPDATE="false"
python -m uvicorn src.main:app --host 127.0.0.1 --port 7860 --workers 1
```

实测结果（2026-10，本机）：**131 项断言全过**

| 检查 | 结果 |
|---|---|
| `GET /health` | 200 `{"status":"healthy"}` |
| `GET /api/ui/home`（未登录） | **401**（登录闸门生效） |
| `GET /api/ui/overview`（不存在的接口） | **404**（修复前是 200 + 首页 HTML） |
| `GET /teams`（前端路由） | 200 + `index.html`（SPA 回落正常） |
| `POST /api/auth/register` | **403**（自助注册已关） |
| `GET /console/login.html`、`/docs` | 200 |
| `scripts/verify_search.py` | 23 / 23 通过（单查询 1.9 ms，索引 19,800 条） |
| `scripts/verify_qa.py` | 37 / 37 通过（本机未配 key → 走检索摘要分支，49 ms） |
| `scripts/smoke_ui_api.py` | 30 / 30 端点通过 |
| `scripts/verify_account.py` | 41 / 41 通过（含改密码把其它设备踢掉） |

> 这次探测顺手修掉一个真问题：SPA 挂在 `/` 且「未知路径回落 index.html」，
> 于是**拼错的接口路径也返回 200 + 一份首页 HTML** —— 写错的接口会被当成正常。
> 现在 `src/main.py` 的 `SPAStaticFiles` 对 `/api/*` 与 `/health` 不回落，直接 404。

内存：本机启动后常驻约 **286 MB**（`python -m uvicorn`，单 worker，任务管理器读数）。
所以 Render 免费档 512 MB 够用但不宽裕，别再加 `--workers`（SQLite + 进程内定时任务，多 worker 会互相打架）。

### 5.1 容器入口脚本单独验过（本机没有 docker 也能验）

镜像里那条「数据不在就自己拉数据包」的分支只在云端容器跑，最容易漏测。用
`scripts/verify_entrypoint.sh` 把它单独跑了一遍：把脚本里写死的 `/app` 换成临时目录、
用桩命令顶替 `uvicorn`/`python`，喂**真数据包**（51.8 MB）走五种情况。

```bash
sh scripts/verify_entrypoint.sh "$TEMP/aifootball-data-pack-v1.tar.gz"   # Git Bash / Linux 均可
```

实测 **18 / 18 通过**：缺库时下载并解包（football.db / search.db / 模型 / 特征 CSV 四样都到位）、
库已存在时不再下载、地址不可用只给警告仍启动、库与模型都缺时给两条警告不崩、
缺检索索引时走 `build_search_index.py` 现场重建；末尾断言 `exec uvicorn … --workers 1`。

**CI 第一次真跑起来时，这一步挂了，挂了两次 —— 两次都是脚本自己的问题，值得记下来**：

1. 数据包发布后 CI 首次执行 runtime 段：131 项服务端断言全过，这一步报 2 项失败
   （`没有提示数据库不存在` / `没有提示模型不存在`）。原因是**场景 4 想验「没配数据包地址」，
   却没有清掉环境里的 `DATA_PACK_URL`** —— 它在 CI 里是 job 级变量，于是这个场景实际又拿到了
   地址、又下了一次数据包，警告当然不出现。本机跑的时候环境里没这个变量，所以一直没暴露。
   修法：场景 1/4/5 都显式写全自己需要的变量（`DATA_PACK_URL=` / `LLM_API_KEY=`）。
2. 修完在登录 shell 下复跑，反而变成 15 项失败、输出全空。原因是脚本里用 `env PATH=… sh …`
   设置环境，而本机 `~/.local/bin/env` 是 **uv 装的一个 328 字节的 PATH 包装脚本**，登录 shell
   下它排在 `/usr/bin/env` 前面，行为不是 coreutils 的 `env`，整个子命令静默无输出。
   修法：不再调用 `env`，改成在子 shell 里 `export` + 前缀赋值（纯 POSIX）。

两种环境（非登录 / 登录 shell）与「带着 `DATA_PACK_URL` 模拟 CI」三种跑法现在都是 18/18。

> 仍然**没有**验的部分（说清楚）：本机没装 docker，所以镜像没有真正 `build` 过 ——
> `Dockerfile` 的层与 `requirements-deploy.txt` 的安装只做了静态核对（依赖与源码 import 对照、
> YAML 语法校验、按生产配置跑真服务）。第一次真正构建在 Render 那边，构建日志第一眼看这个。

## 6. 部署后检查清单

- [ ] 地址能打开，且**未登录时**看不到数据（应该被挡到登录页）
- [ ] 用 `admin` 登录后，首页有真实数字（比赛 12,698 / 球队 240 / 球员 4,745）
- [ ] 预测页有预测、且标注了样本外口径
- [ ] 问答页能返回带引用的答案（没配 key 时应明确说明处于检索摘要模式）
- [ ] **改掉 admin 默认密码**
- [ ] 确认自助注册是关的（打开 `/console/register.html` 提交应被拒）
- [ ] `LLM_API_KEY` 只存在于平台的环境变量里，仓库与镜像里都没有
- [ ] 日志里没有「模型未加载 / 数据库不存在」警告

**排错速查**：

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 打开要等 30~60 s | 免费档休眠冷启动 | 正常；想要常驻就换付费档或路线 B |
| 界面数据全空 | 数据包没进镜像/容器 | 看构建日志有没有下载 `DATA_PACK_URL`；容器里 `ls /app/data/database` |
| 预测报「模型未加载」 | `models/*.joblib` 缺失 | 数据包内容见 §1；确认 `MODEL_DIR` 指向 `/app/models` |
| 检索/问答不可用 | `search.db` 缺失 | 入口脚本会自动重建；也可手动 `python scripts/build_search_index.py` |
| 上传头像后过一阵变回默认 | 免费档磁盘不持久 | 已知限制；要持久化见路线 B |
| 问答老是「检索摘要」模式 | 没配 `LLM_API_KEY` | 在平台环境变量里填；或接受无大模型降级模式 |
| 扫码登录二维码链接打不开 | 缺 `AUTH_PUBLIC_BASE` | 设成服务的公网地址 |

## 7. CI（`.github/workflows/ci.yml`）

推送到 `main` 或开 PR 时自动跑两个 job：

- **static**：`compileall` 语法自检 + `check_deps.py` 依赖体检（不碰数据，秒级）
- **runtime**：装运行依赖 → 下数据包 → 起服务等 `/health` → 跑 `verify_search`（23）+
  `verify_qa`（37）+ `smoke_ui_api`（30）+ `verify_account`（41）+ `verify_entrypoint.sh`（18，
  在 Linux/dash 下把容器入口脚本再验一遍）

**为什么不全跑**：本机那 16 个脚本里有 5 个依赖 Playwright 真浏览器
（`verify_webui` / `verify_ask_ui` / `verify_account_ui` / `_login_flow` / `check_sameorigin`），
放进 CI 每次都要装浏览器，性价比低，所以留本机跑。CI 里跑了 149 项（检索 23 + 问答 37 +
端点冒烟 30 + 账号 41 + 容器入口 18），覆盖检索、问答、全端点冒烟与账号设置。

CI 里**故意不配** `LLM_API_KEY` —— 于是每次都在验证「没有大模型也能用」（检索摘要分支）。

数据包那个 Release 还没上传时，`runtime` 的前置步骤会探测一下 URL：探测不到就在日志里留一条
`::warning::` 并**跳过**后面的运行时步骤（而不是整片标红 —— 免得「还没传数据包」被误读成
「代码坏了」）。上传之后同一个 job 会自动开始跑全量断言，不需要改 `ci.yml`。
