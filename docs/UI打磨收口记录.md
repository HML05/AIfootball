## 0. 本轮打磨的范围与边界

**在范围内（可自由重构）**：`frontend/app.py`、`frontend/admin.py`、`frontend/theme.py`、`frontend/i18n.py`。

**明确未触碰**：`src/`、`scripts/`、`models/`、`config/`、`data/`、数据库模式。UI 层对数据只读（SQLite 直查 + 后端 API）。

**四项硬约束的遵守情况**：

| 约束 | 遵守方式 | 核验 |
|---|---|---|
| 不重命名既有 `T[...]` 令牌键 | 令牌只做**值**的微调与**新增**，键名一律保持 | 全站样式规则键名未变 |
| 不删除既有 Tab / 页面入口 | 用户端 8 页、管理端 10 Tab 条目数量不变（可重样式、可重排序） | 双语回归逐一访存 8 页全通过 |
| 空数据必须走 `empty_state(...)` 并带填充命令 | 统一为 `empty_state(icon, title, desc, command)`，绝不隐藏、绝不报错 | 用户端 26 处 + 管理端 22 处调用 |
| 所有文案经 i18n `t()`，中英双语完整 | 中文原文为词条键；新增内容同步补 EN 词条 | `t()` 漏译 **0** 处 |

**单一样式源**：前后台共用 `theme.py` 的同一份 `UNIFIED_CSS`，由 `apply_theme()` 注入一次；`app.py` / `admin.py` 中无任何独立 `<style>` 注入。

## 2. 设计令牌与全局样式的微调

三项微调都发生在**值**层面，键名一律未动，符合「不得重命名既有 `T[...]`」约束。

### 2.1 弱化文本色提亮（可达性）

| 令牌 | 原值 | 现值 | 原因 |
|---|---|---|---|
| `t3` | `#6b9478` | `#729e80` | 原值在 `bg3` 上仅 **4.26:1**，未达 WCAG AA 正文标准；提亮后 `bg3 = 4.80:1`、`bg2 = 5.38:1` |

提亮后，全部文本色在四层背景（`bg0 / bg1 / bg2 / bg3`）上的对比度**均 ≥ 4.5:1**，核算表内嵌于 `UNIFIED_CSS` 的无障碍注释段，便于后续追溯。

### 2.2 焦点可见性

新增全局 `:focus-visible` 规则：2px 强调色描边 + 2px 偏移 + 4px 圆角；并对侧栏单选组、按钮、折叠面板标题做了针对性补强，保证键盘 Tab 走查时焦点位置**始终可见**。

### 2.3 动效偏好

新增 `@media (prefers-reduced-motion: reduce)`：将动画与过渡时长压到近似 0，并关闭卡片悬停位移。前庭敏感用户不会看到位移与放大。

## 3. 图标体系替换（emoji → Material Symbols）

**动机**：emoji 的字形由操作系统字体渲染，跨平台形状/色彩/基线均不一致，且无法继承文本色，是「模板感」与「拼贴感」的主要来源。全站改用 Streamlit **内置离线**的 Material Symbols Rounded 矢量字体。

**替换规模**：共 **361 处**。

| 文件 | 处数 | 说明 |
|---|---|---|
| `app.py` | 148 | 导航项、区块标题、信息卡、按钮、状态盒、空态图标 |
| `admin.py` | 174 | Tab 标签、区块标题、状态与告警、按钮、空态图标 |
| `i18n.py` | 33 | 词条键与译文前缀中残留的 emoji（导航与 Tab 名） |
| `theme.py` | 6 | 状态盒内置图标（信息 / 成功 / 警告 / 失败 / 传感器 / 足球） |
| `viz.py` | 0 | 图表库内部无 emoji 用法 |

**两种写法（务必区分，否则图标会显示成字面文字）**：

1. **图标 + 文本** → 直接写短代码 `:material/xxx:`，由 Streamlit 在 markdown 文本节点中替换；
2. **纯图标**或**位于 HTML 块内** → 必须经 `theme._icon()` 归一化为 `<span class="msr" aria-hidden="true">xxx</span>`。原因是 `unsafe_allow_html=True` 的 HTML 块不参与短代码的文本替换，短代码会被当字面量打印；`aria-hidden` 同时让装饰性图标对读屏器静默。

例外：`st.set_page_config(page_icon=":material/...:")` 由 Streamlit 官方直接支持，保持短代码即可。

## 4. 国际化为先的最后收口

收尾阶段把「切一次语言就能暴露」的问题**逐处清零**，按发现顺序共收敛三轮：

1. **第 1 轮 —— 控件 id 漂移（缺陷类 1）**：给全部 keyless 且 label/options 含译文的控件补显式 `key=`。侧栏导航是影响最大的一处（切语言直接导致页面跳回首页）。
2. **第 2 轮 —— 选项值漂移（缺陷类 2）**：用户端 4 处、管理端 1 处选择器改为「行号取值 + `format_func` 显示」。这一轮的特点是**缺陷在单语言下完全不可见**，只有「选一个非首项 → 切语言」才会发现选择被吞掉。
3. **第 3 轮 —— 库内中文未过漏斗（缺陷类 3）**：新增 `txt_i()`，把取自数据库的中文枚举值（联赛名，7 处）接入 i18n。这类缺陷的特点是**代码里没有裸中文**，所以传统「扫硬编码中文」的检查查不出来——中文来自数据行，而非源码字面量。

三轮之后，静态审计（控件语言耦合 + i18n 覆盖）与运行时双语回归（24 项）**双双通过**。

## 5. 明确「未做」的事

为保持改动可控、避免越界，以下事项**本轮有意不做**，均已在评审报告第 4 节登记为可排期的缺口：

| 未做事项 | 原因 |
|---|---|
| 多条件筛选区的「一键重置」 | 属功能新增，非本轮缺陷修复范围；纯 UI 层改动，成本低，可独立排期 |
| URL 深链与键盘快捷键 | Streamlit 多页架构不提供稳定路由，需架构级改造 |
| 业务异常统一错误卡 | 需新增 `error_card()` 组件并替换全站 `st.error`，属组件库扩展 |
| 应用内独立「帮助」入口 | 现帮助信息散落在管理端说明与 `docs/`，尚可接受 |
| 任何 `src/` / `scripts/` / `models/` / `config/` / `data/` 的改动 | **硬约束**：UI 与数据/模型链路分工边界，一律不触碰 |
